# BUG — disposed window context menu on right-click (2026-09-22)

**Reported by owner:** In the locally published five-language Windows preview from `feature/functional-dialog-placement`, right-clicking a window row in the sidebar produced an unhandled `System.ObjectDisposedException` for `System.Windows.Forms.ContextMenuStrip`. The supplied call stack passes through `ToolStripDropDown.SetVisibleCore`, `ContextMenuStrip.SetVisibleCore`, `ToolStripDropDown.Show`, and `Control.WmContextMenu`. The screenshot and full environment-specific exception dump remain in the conversation; do not publish them or personal window names in this public repository. Actual observed result: **FAIL** for right-click/window menu, not a verified fix.

**Source-based diagnosis (strong hypothesis, GUI retest pending):** `WindowManagement.ShowWindowMenu` creates a new `ContextMenuStrip`, displays it during the TreeView's right-click event, and executes `menu.Dispose()` synchronously in `menu.Closed`. WinForms can still be processing the context-menu transition/WM_CONTEXTMENU when `Closed` fires. That premature disposal is consistent with the supplied stack; do not claim the precise native event ordering is proven without instrumented Windows reproduction. Additional native context-menu handling may also need investigation if the first fix is insufficient.

**Narrow mitigation staged, NOT RUN:** The development-only script `development/fix-context-menu-lifetime-20260922.ps1` on `feature/functional-dialog-placement` replaces the synchronous disposal with a form-dispatched deferred dispose after the active menu event unwinds. It guards branch, clean tree and exact source blob; uses the owner's portable .NET SDK for five-language smoke and fresh Windows publish; optionally commits/pushes; and automatically starts the newly published EXE only if no older WinSidebar instance is running. It does not alter preferences, process identities, user data or other Git repositories. The script's presence does **not** mean the fix was applied, compiled or interactively verified. No GitHub Actions or FILEBRIDGE.

**Retest required:** close the exception dialog and old WinSidebar via its tray exit; run the script once on a clean local feature branch; right-click several list entries repeatedly; open/cancel Rename and Ignore; use Shift+F10 / Apps; right-click empty space, tray menu and language selector; verify no duplicate menu, crash or missing context actions. Check dialog positioning separately. If it still fails, capture only a redacted stack and do not mark PASS or release. Existing `main` / v1.0.0 is unchanged.
