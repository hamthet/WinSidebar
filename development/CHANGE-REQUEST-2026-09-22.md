# Change request CR-2026-09-22 — window management and shortcut preferences

**Status: ACCEPTED REQUIREMENTS / IMPLEMENTATION NOT VERIFIED.** Requested by product owner on 2026-09-22. Applies to `develop`; supersedes conflicting assumptions in `PLAN.md`, `PRODUCT-REVIEW.md`, `VERIFICATION.md` and ADR-007/009 of `DECISIONS.md`. Source of truth for these changes until the canonical documents are consolidated. Existing statements that Calculator/Settings should remain deliberately excluded are obsolete. Do not describe the user-approved preference behavior as a confirmed bug.

## Product intent and scope

- The window tree should show **actual interactive windows approximately matching those exposed by Windows Alt+Tab**, grouped by monitor. It is *not* a list of every running process. Windows exposes no simple guarantee that `EnumWindows` and the Alt+Tab shell view produce identical sets; compare observed results on supported Windows 10/11 builds and document exceptions. Existing filters for visibility, tool/owned windows and DWM cloaking require review for fidelity. Specifically remove the unconditional Portuguese/English title and process-name exclusions of Calculator and Settings. They were an earlier workaround for **phantom windows shown when the apps were not open**, not a product requirement to suppress legitimate Calculator/Settings windows. Do not simply remove filters and call the phantom-window defect fixed: reproduce the original case and identify the root cause (e.g., hidden app frame/owner/desktop state) without excluding genuinely open apps.
- Context menu on a real window: **Rename window…**, **Reset window name** (when aliased), **Ignore this application**. Rename affects *only WinSidebar's displayed label*, never the other application's Windows title, HWND, executable or keyboard focus. Five Calculator windows must be independently distinguishable. Preserve the alias during ordinary refresh/title changes for the same live window; avoid alias transfer if an HWND is reused. Initial implementation may scope aliases to the live window/session; explicitly disclose that they do not persist after the window closes or WinSidebar restarts unless a reliable durable window identity is designed and tested. Never apply a single process-wide alias to all five windows.
- Ignore is **per application**, not per window title: selecting a window identifies a stable, nonlocalized application identity (prefer validated executable path; fall back to normalized executable/process name if path cannot be accessed, with disambiguation and a visible explanation). All matching current and future windows are hidden. Do not write a wildcard or an ambiguous empty identity. Preserve the list locally and reversibly. Add **Manage ignored applications…** to a permanently reachable tray/side menu, list each rule, allow individual removal and an optional clear-all action with confirmation. Removing the last visible application must never remove access to the management control. Never ignore WinSidebar itself. Applying/removing a rule refreshes the tree immediately and preserves other preferences. Path-based rules must have documented behavior if the executable is moved or renamed.
- Replace the section title `PASTAS / WEB` with localized **Atalhos / Shortcuts** (and appropriate Spanish/Russian/Chinese equivalents). In the *same heading row* as the existing configuration gear, add **Restore defaults** and **Save preferences** controls. The header must remain usable at the narrowest supported sidebar width and at 100/150/200% scaling. Prefer compact icons with localized tooltips and accessible names, without relying on icon shape alone.
- **Save preferences** must have a real, explicit persistence effect and report success or actionable failure. At minimum save current sidebar geometry/monitor/browser/language, ignored-application rules and the four shortcut entries, using existing storage formats where compatible. Auto-saving on existing controls may remain, but the explicit control must not be a decorative no-op. Avoid a misleading success popup if any write failed; do not lose the previously saved state on partial failure. Document atomicity boundaries and recovery if multiple files are involved.
- **Restore defaults** requires confirmation and restores the four generic shortcuts, browser mode, sidebar position/width, ignored rules and transient aliases, without deleting arbitrary folders, browsing history or user-imported icon files. Language behavior must be explicit: **proposed** preserve the currently selected language to keep the confirmation understandable; product owner can change this before implementation. Preserve existing state if persistence of the reset fails; report partial-save failure instead of claiming full reset. UI must refresh immediately. Existing user data must not be silently overwritten without the confirmation.

## Data / compatibility contract

- Existing `%LOCALAPPDATA%\WinSidebar\settings.ini` and `shortcuts.xml` retain their current recognized fields and internal stable IDs (`folder`, `website`, icon tokens). Add a separate versioned, bounded ignored-apps store or explicitly version the existing storage if needed. No untrusted JSON/XML expansion, arbitrary process execution, leaked machine paths in logs or repo. Store no application window title in the global ignore rule.
- Window identity: use HWND plus PID/process-lifetime guard while live, clean stale aliases when enumerated windows disappear; handle a rapid close/reopen and two same-title windows. Do not persist raw HWNDs across restarts. Avoid using translated visible labels as identity.
- Owner-reported status: current preferences behavior **tested and approved** by owner for their existing workflow. Prior dossier entries alleging a confirmed preference defect must be reclassified as *unverified edge cases*. **Cross-version preference migration testing is explicitly out of scope at the owner's direction**; do not claim cross-version compatibility was tested. Preserve existing files conservatively in implementation and disclose residual upgrade uncertainty. New save/restore/ignore persistence paths are new functionality and require their own tests.
- Do not fold any of this work into release `main` or call the application multilingual before five runtime catalogs and UI verification pass. `development/**` stays development-only, never in a customer ZIP or final product tree.

## Acceptance scenarios (record actual results in VERIFICATION and LOG)

| ID | Scenario / pass condition |
| --- | --- |
| WM-01 | Open Calculator and Settings: their actual Alt+Tab windows appear; close them: no phantom entries remain. Compare to Windows Alt+Tab with a documented environment. |
| WM-02 | Open five Calculator windows with identical base titles; rename each differently; refresh, select and activate each correct HWND; other applications' window titles remain unchanged. |

| WM-05 | Remove Calculator from ignored list, including after restart: eligible live windows reappear. Confirm two similarly named but distinct executables are not accidentally conflated. |
| WM-06 | Existing shortcut names, browser choice, monitor placement and language remain unchanged when renaming or ignoring windows; ignored rules persist after save and restart. |
| SP-01 | Section label is localized `Atalhos`/`Shortcuts`; gear, restore and save appear on same row and are keyboard/screen-reader reachable at smallest width and 100/150/200% DPI. |
| SP-02 | Change settings and shortcuts; Save preferences; restart; verify persisted values, ignored rules, language, and no false success on denied writes. |
| SP-03 | Restore defaults > Cancel preserves state; Confirm resets specified fields/rules/aliases and shortcuts while preserving external folders/files; partial save failure is surfaced and recovery documented. |
