# Implementation constraints — pending code work

CR-2026-09-22 is the authoritative new behavior contract. **This file records design hazards; no code change or validation is implied by a requirements commit.**

1. `EnumWindows` is not an Alt+Tab API. The previous hard-coded Calculator and Settings filters were a workaround for phantom windows. Do not remove their filters without a regression scenario showing closed apps do not appear; test Win32 Calculator and packaged Calculator/Settings where available. UWP `ApplicationFrameHost` is a host process, not a safe ignore identity for all Windows Store applications; resolve the hosted app where possible or disable ignore with an explanation.
2. A process is not a window: five Calculator windows can share PID/executable. Aliases must be tied to the live window, not PID, title, or executable. HWND alone may be recycled; couple with PID/lifetime and clear stale aliases. Persisting aliases across application restarts needs a deliberate durable identity not currently available; specify per-session aliases if no reliable identity exists.
3. An ignore rule should identify the actual application, preferably by executable path or package identity; process-name fallback has potential collisions. Explain rule scope to the user. Keep an always-reachable manager in the notification-area menu, independent of the tree contents. Persist changes with bounded input, safe JSON/XML parsing, atomic writes and actionable errors.
4. The narrowest sidebar is 211 px, and the heading also contains the gear. Two extra controls must fit without crowding text, including under scaling and five languages. An icon-only button still needs a localized accessible name and tooltip. Confirm destructive reset, allow cancel, retain the selected language unless the owner decides otherwise.
5. Original `SaveSettings()` swallows certain IO exceptions. A new explicit Save button must call a strict/reporting save path rather than the swallowing helper. Do not treat the owner's approval of *existing* preference reliability as a new Save/Restore test. No cross-version migration test is required by the owner.
6. A locale change after this feature must translate every new context-menu item, manager label, alias dialog, reset/save message, heading, tooltips and accessible names. Integrate feature implementation and localization on `develop`; no premature user-facing release or README claims.

Track code commits and executed CI/manually observed outcomes in `LOG.md`, and ensure this engineering document is excluded from the release branch and ZIP.
